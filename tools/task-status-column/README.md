# 既存タスクシートへの「タスク状況」列の新設+色分け手順

先方運用中のタスク管理スプレッドシートに、**「タスク状況」プルダウン列を1列新設**し、その値をキーにした**条件付き書式で行全体を色分け**する単体スクリプトです。ステータスの項目・配色は LINEタスク管理Bot の「タスク一覧」シートと同一です。Bot本体とは独立しており、対象スプレッドシート側だけで完結します(GASの常駐・トリガーはありません)。

`tools/hpb-status-colors`(既存列への色分け移植)との違いは、**列の挿入というシート構造の変更を伴う**ことです。既存の「タスク状況（進捗）」列は時系列メモとしてそのまま残し、一切触れません。セルの既存値・既存の条件付き書式ルールにも触れません。

## 必ずシートのコピーで試してから本番に適用する

列挿入を伴うため、**本番シートへの適用前にコピーで一度試すことを必須手順**とします。

1. 対象スプレッドシートのメニュー **ファイル > コピーを作成** でコピーを作る
2. コピー側で下記「適用手順」を最後まで実施する
3. 次のチェックリストを確認する
   - [ ] 「タスク状況」列が「タスク状況（進捗）」列の直後に入った
   - [ ] 新設列のセルに10項目のプルダウンが出る
   - [ ] 各値を選ぶと行全体の色が変わる(「未対応」は白のまま=仕様どおり)
   - [ ] 既存の色・数式・フィルタ・プルダウンが壊れていない(特に下記「制約」の列番号参照)
   - [ ] `setupTaskStatusColumn` をもう一度実行しても列が二重に入らず、ルールも重複しない(冪等)
   - [ ] `removeTaskStatusFormatting` で色ルール・プルダウンが消える(列は残る=仕様どおり)
4. 問題がなければ本番シートで同じ手順を実施する(編集する人が少ない時間帯を推奨。処理自体は数秒)

## 適用手順

1. 対象スプレッドシートを開き、メニューの **拡張機能 > Apps Script** を開く
2. エディタに `setupTaskStatusColumn.gs` の内容を貼り付けて保存する
3. ファイル冒頭の `TS_SETTINGS` を対象シートに合わせて編集する(下記「設定項目」)
4. エディタで関数 `setupTaskStatusColumn` を選択して実行する(初回はアカウントの承認ダイアログが出ます)
5. 実行ログに `[OK] タブ名: 「タスク状況」列を◯列に新設 / 既存ルール保全 n件 / 色ルール追加 9件 / プルダウン: …` が出ることを確認する
6. 新設列でプルダウンから値を選び、行の色が変わることを確認する

対象タブが見つからない場合は、ログにそのスプレッドシートの全タブ名と gid の一覧が出ます。それを見て `TS_SETTINGS` を直してください。

## 設定項目(`TS_SETTINGS`)

| キー | 説明 |
|---|---|
| `sheetId` | 対象タブの gid。対象タブを開いたときの URL の `gid=` の後ろの数値をそのまま書く。`null` にするとタブ名で探す |
| `sheetName` | タブ名で指定する場合に使用(`sheetId` が `null` のとき) |
| `newHeader` | 新設する列の見出し(既定「タスク状況」)。再実行時はこの見出しの列を再利用する |
| `anchorHeader` | この見出しの列の**直後**に新設列を挿入する(既定「タスク状況（進捗）」)。**実際の見出しセルの値をコピーして貼る**のが確実(表記が1文字でも違うと見つからない。ただし空白と全角/半角括弧の違いは自動で吸収する) |
| `headerRow` / `firstDataRow` | 見出しの行(通常 1)とデータの開始行(通常 2) |
| `lastColumnLetter` | 色を塗る範囲の右端の列レター。`''` なら最終列を自動判定 |
| `VALIDATION_MODE` | プルダウンの扱い。`'missing-only'`(未設定なら設定・既定)/`'none'`(触らない)/`'force'`(上書き) |
| `STATUS_STYLES` / `STATUS_ORDER` | 状況の値と色・プルダウンの表示順(Bot本体と同一のコピー) |

## 色の定義(Bot本体「タスク一覧」シートと同一)

| タスク状況 | 行の色 |
|---|---|
| 未対応 | 白(既定) |
| 依頼中 | `#f4cccc` |
| 作業完了・未チェック | `#f4921e` |
| チェック完了・残りお客様連絡 | `#ec47dd`(文字白) |
| タスク完了済み | `#b7b7b7` |
| 佐藤さん提出 | `#ffe14d` |
| 急ぎの対応 | `#ff2b22`(文字白) |
| 反映待ち | `#4a86d8`(文字白) |
| お客様連絡待ち | `#b6d7a8` |
| 対象外 | `#d9d9d9`(取り消し線) |

## 動作の要点

- **冪等**: 再実行しても、見出し「タスク状況」の列が既にあればそれを再利用し、色ルールを張り替えるだけ。列が二重に入ることはありません
- **既存の条件付き書式は保全**: 追加するのは本スクリプトの9ルールのみ。自前ルールは数式の一致で識別して張り替えます
- **自前ルールは末尾に追加**(既存ルール優先)。条件付き書式は上にあるルールが優先のため、同じ行に色を塗る既存ルールがあるとそちらが勝ちます。状況の色を優先したい場合は、シートの「表示形式 > 条件付き書式」でルールを上へ並び替えてください
- **プルダウンは選択肢以外の入力を拒否**します(誤記入=色が付かない事故の防止)。行まるごとのコピペ運用で貼り付けが拒否される場合は、スクリプト内 `tsApplyValidation_` の `setAllowInvalid(false)` を `true` に緩めてください

## 制約(運用上の注意)

- **【最重要】列番号の「数値」で参照している数式はずれます。** 列挿入により、セル参照(`=H2` 等)・条件付き書式・フィルタ・保護範囲・名前付き範囲は自動でシフトされますが、次のものは自動調整されません:
  - `VLOOKUP(…, 8, …)` の列番号、`INDEX`/`OFFSET`/`CHOOSECOLS` の列指定
  - `QUERY(…, "select Col8")` の Col 番号
  - **別のスプレッドシートからの参照**(`IMPORTRANGE` や他ブックの数式。範囲文字列が固定のため)
  挿入位置(「タスク状況（進捗）」列)より右の列をこれらで参照していないか、適用前に先方へ確認してください。コピーでの試行時のチェック項目でもあります
- `TS_SETTINGS` の設定(列や状況の表記)を**変更して再適用する場合は、先に変更前の設定のまま `removeTaskStatusFormatting` を実行**してください(自前ルールの識別は現在の設定から生成した数式との一致で行うため)
- 適用後に右側へ列を追加した場合、色塗り範囲は旧右端のままです。**列を増やしたら `setupTaskStatusColumn` を再実行**してください(冪等なので安全)
- プルダウンの「既存の設定があるか」は `firstDataRow` のセル1つで代表判定します(`missing-only` 時)

## 撤去手順(やり直し)

1. 関数 `removeTaskStatusFormatting` を実行する — 本スクリプトが追加した**色ルールと見出しメモ、および「タスク状況」列のプルダウンだけ**を除去します(他の条件付き書式・他列のプルダウンには触れません。「タスク状況」列のプルダウンは出所によらず除去されます)
2. **挿入した「タスク状況」列自体は削除しません**(入力済みデータの保護のため)。列ごと不要な場合は、列見出しを右クリック > 「列を削除」で手動削除してください

## 色が付かないときの確認点

- 状況の値の**表記ゆれ**(全角/半角・中黒・スペースの有無)が `STATUS_STYLES` の `status` と一致しているか
- `headerRow` / `firstDataRow` が対象タブの実レイアウトと合っているか
- 「未対応」は白(既定色)のためルールがありません(仕様どおり)
- 既存の条件付き書式が同じ行を塗って勝っていないか(上記「動作の要点」)
