# 本番環境切替手順(テスト運用 → 本番運用)

作成日: 2026-08-04

テスト運用中の現環境を、本番の社内通知グループ・実サロングループへ切り替えるための手順書。
新規構築の手順ではない(構築済み環境の設定切替と展開)。ゼロからの構築は `docs/setup.html` を参照。

---

## 0. 前提(切替前の状態)

以下がすべて満たされていることを確認してから着手する。

| 項目 | 状態 |
|---|---|
| GASプロジェクト・スプレッドシート | 構築済み・テスト運用で稼働中 |
| LINE公式アカウント(記録用) | 作成済み(Messaging API有効・Webhook接続済み・応答/あいさつOFF・グループ参加ON・再送OFF) |
| Dropbox | 発注元アカウントのアプリ・リフレッシュトークンへ切替済み(保存先 `/お客様/お預かり画像/{yyyy.M.d}{サロン名}/`) |
| Webhookデプロイ | 最新バージョンに更新済み(`clasp list-deployments` で確認。§6 留意-1参照) |
| トリガー | `installTriggers()` 実行済み(5分おき分析+10〜11時サマリ) |
| サマリ仕様 | 「新着連絡サマリ」(前回送信以降の到着分一覧・土日祝/年末年始スキップ) |
| 先方既存タスクシート | 「タスク状況」列+色分けツール適用済み(タスク進捗管理は先方シートへ一本化) |
| `SUMMARY_GROUP_ID` / `ADMIN_GROUP_ID` | **テスト用社内グループのIDを仮設定中**(本手順で本番値へ差し替える) |

**切替の開始条件: 社員からの本番切替OK連絡があること。**

## 1. 切替前チェック(当日朝までに)

1. 最新コードを `clasp push` し、GASエディタで `refreshGuideAndHeaders()` を実行する
   (稼働中シートの「使い方」タブとタスク一覧ヘッダーを現行の説明へ更新する。`setupSpreadsheet()` は
   既存シートをスキップするため、これを実行しないと旧い説明が残る)。
2. GASエディタで `checkConfiguration()` を実行し、全項目OKを確認する。
3. `clasp list-deployments` でWebhookデプロイが最新コードのバージョンであることを確認する
   (直近で `doPost` 系のコードを変更していれば `clasp update-deployment <deploymentId>` を先に実施)。
4. 平日に `sendDailySummary()` を手動実行し、テストグループへFlex形式のサマリが届くことを確認する
   (土日祝は関数冒頭の判定でスキップされ届かない。手動実行は `SUMMARY_LAST_SENT_AT` を更新する点に注意)。
5. 必要に応じて GASエディタで `test_*` の回帰テストを実行する(§9.1)。

## 2. 本番の社内通知グループの準備

**招待 → 即「社内」化 → メンバー招待** の順を厳守する(先にメンバーを入れると、
「社内」化前の発言が顧客メッセージとして記録・分析される)。

1. 本番の社内通知グループ(約30名)にBotを招待する。既存グループを使う場合は
   他社の公式アカウントが参加していないことを先に確認する(1グループに公式アカウントは1つまで)。
2. 顧客マスタに行が自動追加されるので、**直ちにC列「状態」を「社内」に変更**する。
3. エラー・警告通知用の管理者グループ(少人数推奨)にも同様にBotを招待し、「社内」化する。
   通知グループと兼用してもよいが、エラー通知も約30名分の通数を消費する点に留意。

## 3. 自社メンバーuserIDの収集

1. 社内通知グループ(状態「社内」)で、自社メンバー全員に1回ずつ発言してもらう。
2. 設定シート「自社メンバーuserIDリスト」へ自動追記されることを確認する。
3. 以後、新メンバーは社内グループで1回発言すれば自動登録される。退職時はリストからID削除+
   LINEグループ退出の両方を行う(残ったまま発言すると自動で再登録される)。

## 4. LINEライトプランへの変更

**本番グループ宛の配信を始める前に必ず実施する。** 約30名への毎朝1通で約900通/月となり、
無料枠(200通/月)を初月から超過するため。LINE Official Account Manager から
ライトプラン(月5,000円 税別・5,000通/月)へ変更する。

## 5. スクリプトプロパティの切替(切替コア作業)

1. 顧客マスタA列から本番グループのグループIDを控える(通知用・管理者用の2つ)。
2. スクリプトプロパティを差し替える:
   - `SUMMARY_GROUP_ID` → 本番の社内通知グループID
   - `ADMIN_GROUP_ID` → 本番の管理者グループID
3. `SUMMARY_LAST_SENT_AT` を**現在日時に手動更新する**(書式は既存値に合わせる)。
   テスト時の値のままだと、翌朝の初回サマリに**テスト期間中の起票分まで**本番グループへ流れる。
   削除した場合は「前営業日10:00以降」が対象窓になる点にも注意。
4. `checkConfiguration()` を再実行し、全項目OKを確認する。

## 6. テストデータの整理

1. タスク一覧のテスト起票行: タスク状況を「対象外」へ変更する(行削除はしない。証跡として残す)。
   件数が多い場合は行削除でもよいが、非表示のシステム列ごと削除すること。
2. テストサロングループ: 継続利用しないならBotを退出させる(顧客マスタの状態が自動で「退出」になる)。
   動作確認用に残す場合はそのままでよい(起票は継続する点に留意)。
3. テスト用社内グループ: 残す場合は状態「社内」のままにする(誤起票防止)。

## 7. 切替翌朝の確認

1. 平日の10時台に、本番の社内通知グループへ新着連絡サマリが届くことを確認する
   (新着0件でも「新着の連絡はありません」が届く=正常稼働の確認)。
2. 「タスク一覧を開く」ボタンからシートが端末の標準ブラウザで開くことを確認する。
3. エラーログシートに新規エラーがないことを確認する。

## 8. パイロット展開(5〜10店舗)

1. 対象サロンを確定し、案内文(`docs/manual.html` 第5章の例文)を担当者から送る。
   招待手順・注意点も同章にまとめてあるため、担当者へはマニュアル第5章を案内する。
2. 各サロンのグループにBotを招待する。招待前に他社Botの不在を確認する(該当時は新グループを作成)。
3. 顧客マスタへの自動追加と、サロン名(LINEグループ名)の自動記入を確認する。
   表記を変えたい場合はB列を直接上書きする。
4. 最初の実依頼で一連の流れ(受信→ログ→5〜15分でタスク起票→翌朝サマリ掲載)を確認する。
   画像を含む依頼ではDropbox保存とリンク記録も確認する。
5. 1〜2週間の運用で精度・運用を確認後、対応漏れリスクの高いサロンから段階拡大する。

## 9. 切戻し手順(問題発生時)

- **通知だけ止めたい**: GASのトリガー画面で `sendDailySummary` のトリガーを削除する
  (分析・記録は継続。再開は `installTriggers()`)。
- **通知先をテストへ戻す**: `SUMMARY_GROUP_ID` / `ADMIN_GROUP_ID` をテストグループIDへ戻す。
- **記録自体を止めたい**: LINE DevelopersコンソールでWebhookの利用をOFFにする
  (復旧はONに戻すだけ。URL・デプロイの変更は不要)。
- サロングループからのBot退出は最終手段とする(再招待の手間と先方への説明が必要になるため)。

## 留意事項

1. **Webhook(doPost)系のコード変更は `clasp push` だけでは反映されない。**
   必ず `clasp update-deployment <deploymentId>` で新バージョンを発行する(URL不変・LINE側再設定不要)。
   時間主導トリガーとエディタ手動実行は push のみで反映される。
2. 通数は送信前に自動チェックされ、しきい値(4,500通)超過で管理者グループへ警告が届く。
   届いた場合は月内の配信可否と店舗展開ペースを見直す。
3. サマリは土日祝・年末年始(12/29〜1/3)に届かないのは仕様。祝日判定のAPI取得に失敗した日は
   エラーログに記録のうえ送信側に倒れる。
4. 本書はグループID・トークン等の実値を記載しない。実値はGASのスクリプトプロパティおよび
   顧客マスタで管理する(リポジトリ・公開ドキュメントには書かない)。
